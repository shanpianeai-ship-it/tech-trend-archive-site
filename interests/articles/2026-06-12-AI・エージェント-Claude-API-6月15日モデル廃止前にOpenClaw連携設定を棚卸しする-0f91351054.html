Summary

AnthropicのClaude APIでは、claude-sonnet-4-20250514 と claude-opus-4-20250514 が2026年6月15日に退役予定である。

Claude API 6月15日モデル廃止前にOpenClaw連携設定を棚卸しする

要約

AnthropicのClaude APIでは、claude-sonnet-4-20250514 と claude-opus-4-20250514 が2026年6月15日に退役予定である。退役日を過ぎると、対象モデルへのリクエストは失敗する。推奨移行先は、Sonnet 4が claude-sonnet-4-6、Opus 4が claude-opus-4-8 である。

今回のeveningポールは0票だったため、候補一覧から重要度と個人適合度が高いこのテーマを選んだ。理由は単純で、OpenClaw、Codex、各種Cron、ローカルスクリプト、連携サービスのどこかに古いClaudeモデルIDが残っていると、6月15日以降に自動処理が突然止まる可能性があるためである。

棚卸しの焦点は「新しい一番強いモデルを選ぶ」ことではなく、「固定モデルID、エイリアス、外部サービスのClaudeモジュール、環境変数、cron payload、ワークスペース内の設定ファイルを見つける」ことにある。モデル変更はコスト、トークン数、thinking設定、データ保持条件にも影響するので、単純な文字列置換だけで済ませない方がよい。

なぜ今見る価値があるか

2026年6月12日夜時点で、退役予定日まで残り3日である。Anthropicのモデル廃止ページは、退役日を過ぎたモデルへのリクエストは失敗すると説明している。つまり、検証用の古いスクリプトや、普段はあまり触らない自動化ジョブほど危ない。

ClaudeのモデルIDは「古い名前でもしばらく動く」期間があるため、日常利用だけでは問題に気づきにくい。だが、Cronや外部連携は人間がその場で修正できない時間帯に動く。興味レポート、X投稿、文書整理、画像処理のような定期ジョブにClaude APIを噛ませている場合、モデル廃止は小さな設定ミスではなく運用停止要因になる。

また、2026年6月9日にClaude Fable 5とClaude Mythos 5が出ており、Claudeモデルの選択肢が増えている。移行先を claude-sonnet-4-6 や claude-opus-4-8 に寄せるだけなら比較的保守的だが、Fable 5へ上げる場合は価格、30日データ保持、常時adaptive thinkingなども見る必要がある。モデル名の棚卸しと、モデル選定の判断を分けておくと事故が少ない。

調査メモ

Anthropic公式のModel deprecationsでは、2026年4月14日にClaude Sonnet 4とClaude Opus 4の退役予定が通知され、退役日は2026年6月15日とされている。対象のAPI model nameは次の2つである。

廃止対象退役予定日推奨移行先
claude-sonnet-4-202505142026-06-15claude-sonnet-4-6
claude-opus-4-202505142026-06-15claude-opus-4-8

同じページでは、モデル状態をActive、Legacy、Deprecated、Retiredに分けている。Deprecatedはまだ動くが推奨されず、Retiredになると利用できない。Claude API、Claude Platform on AWS、Microsoft FoundryはAnthropic側の退役スケジュールに従う一方、Amazon BedrockやVertex AIなどのパートナー運営基盤は別スケジュールになる可能性がある。

棚卸しでは、まず文字列検索で古いIDを探すのが現実的である。見るべき文字列は最低限、claude-sonnet-4-20250514、claude-opus-4-20250514、短い別名として使っていそうな claude-sonnet-4、claude-opus-4、設定名としての ANTHROPIC_MODEL、CLAUDE_MODEL、model:、modelName あたりである。

OpenClaw/Codex周辺では、次の場所を確認対象にするとよい。

  • エージェントやCronのpayloadに埋め込んだモデル指定
  • ワークスペースやプロジェクトの .env、設定YAML、JSON、TOML
  • ローカルのNode/Pythonスクリプトに直書きしたClaude API呼び出し
  • MCP、プラグイン、外部サービス連携のモデル設定
  • Make、Zapier、n8nのような自動化SaaSのClaudeモジュール

移行先は、費用と用途で分けるのが現実的である。Anthropicのモデル一覧では、claude-sonnet-4-6 は速度と知能のバランス型、claude-opus-4-8 は複雑推論や長期エージェント作業向けのOpus-tierモデルと説明されている。価格は、Sonnet 4.6が入力100万トークンあたり3ドル、出力100万トークンあたり15ドル、Opus 4.8が入力5ドル、出力25ドルである。Fable 5は入力10ドル、出力50ドルで、30日データ保持要件もある。

Migration guideを見ると、新しいClaudeモデルではthinkingやprefillまわりに差がある。特にFable 5やMythos 5はadaptive thinkingが常時有効で、thinking: {"type": "disabled"} のような指定はエラーになる。古い自動化コードがthinking設定やassistant prefillに依存している場合は、モデルIDだけを置換して終わらせると別の400エラーに変わる可能性がある。

個人向けの読みどころ

個人向けには、「趣味の自動化がいつの間にか止まるのを防ぐ棚卸し」として扱うのがよい。興味レポート、X運用、文書整理、画像処理のような定期処理は、毎日動いているからこそ1回止まるまで気づきにくい。

最初にやることは、リポジトリ単位の検索で古いモデルIDを洗い出すことだと思う。候補コマンドは次のようなものになる。

``bash rg -n "claude-(sonnet|opus)-4-20250514|claude-sonnet-4|claude-opus-4|ANTHROPIC_MODEL|CLAUDE_MODEL|modelName|model:" [内部パス] ~/.openclaw ``

ただし、実行結果には秘密情報や個人設定ファイル名が混ざる可能性があるので、公開記事には貼らない。実務上は、検出した場所を「すぐ修正」「検証してから修正」「外部サービス側で確認」に分けるのがよい。

判断基準は次の3つで足りる。

  • 低コスト・日次処理: まず claude-sonnet-4-6 を候補にする
  • 長文調査・コード修正・判断が重い処理: claude-opus-4-8 を候補にする
  • 最高性能を試したい処理: claude-fable-5 は価格とデータ保持条件を確認してから使う

OpenClaw運用では、モデル指定を各Cron本文に直書きしすぎない方がよい。可能なら、用途別に「既定の軽量モデル」「重い調査モデル」「画像・ブラウザ検証用の別枠」のように分け、Cronのpayloadには用途だけを書く方が後から移行しやすい。

注意点

この記事は公開情報に基づく運用メモであり、Anthropic、OpenClaw、Codex、外部自動化SaaSの契約・課金・データ保持設定を保証するものではない。実際の移行前には、利用中の管理画面、APIログ、請求設定、組織のデータ保持条件を確認する必要がある。

Bedrock、Vertex AI、Microsoft Foundry、Claude Platform on AWSでは、モデルID、利用可能リージョン、退役スケジュール、価格、データ保持条件がClaude API本体と異なる場合がある。特にパートナー基盤を使っている場合は、Anthropic公式ページだけでなく、利用している基盤側のモデル一覧も確認する。

また、rg で見つからないから安全とは限らない。外部サービスのGUI設定、暗号化されたSecrets、クラウド側の環境変数、チームメンバーの個人設定、古いバックアップには残っている可能性がある。最低限、直近で動くCronと、失敗すると困る自動化から順に確認するのが現実的である。
