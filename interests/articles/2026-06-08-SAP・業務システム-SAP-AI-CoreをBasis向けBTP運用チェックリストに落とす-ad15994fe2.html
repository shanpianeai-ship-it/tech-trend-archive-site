SAP AI CoreをBasis向けBTP運用チェックリストに落とす

要約

SAP AI Coreは「AIを動かす基盤」だが、Basis視点では単なる新サービスではなく、BTPサブアカウント、XSUAA、サービスキー、resource group、コンテナ実行、オブジェクトストア、監査ログが組み合わさった運用対象として見るのがよい。

特に見るべき軸は、1. 誰がどのrole collectionで管理できるか、2. service keyや証明書をどう保護・ローテーションするか、3. resource groupでワークロードとsecretを分けられているか、4. Kubernetes workload templateがSAP側の制約に弾かれないか、5. SAP Security Patch DayやBTP側の変更をどう運用カレンダーに入れるか、の5つ。

なぜ今見る価値があるか

SAPのAI機能はJoule、Generative AI Hub、AI Core/AI Launchpad、BTP上の拡張とつながっており、従来のABAPサーバやS/4HANAだけを見ているBasis運用では境界が曖昧になる。AI Coreの公式資料はKubernetes、OAuth、resource group、secret、audit logを前提にしているため、Basis担当が「どこまで自分の監視・権限・棚卸し範囲か」を決める材料になる。

もう一つの理由は、SAP Security Patch Dayとの接続である。SAPは毎月第2火曜日にSecurity Patch Dayを運用しており、2026年6月は6月9日が該当する。AI Core単体の脆弱性だけを待つのではなく、BTP、SDK、コンテナイメージ、CI/CD、接続先のobject storeやsecret管理まで含めて、月次の確認項目へ落とす価値がある。

調査メモ

1. 責任分界点は「SAP管理Kubernetes」でも運用責任が消えるわけではない

SAP AI CoreのワークロードはSAP側の管理基盤上で動くが、顧客側はresource group、service key、secret、object store、template、実行・デプロイ設定を扱う。公式資料では、tenant levelのexecutablesとresource group levelのruntime entitiesが分けて説明されており、executions、deployments、configurations、artifacts、generic secretsは特定のresource groupに属する。

Basis向けには、以下のように分けると扱いやすい。

領域Basisが見るべきこと
BTP subaccountAI Core instance、role collection、監査ログの所在
XSUAA/service keyclient secretまたはx.509証明書、token取得、ローテーション
Resource group業務、環境、利用者単位の分離、default依存の有無
Secret/object store同じbucket/IAM userの使い回し禁止、削除・作成ログ
Workload templateroot実行、権限昇格、capability追加などの禁止設定
Patch/変更管理SAP Security Patch Day、SDK/コンテナイメージ、接続先更新

2. Kubernetes securityは「開発者任せ」にしない

SAP Help PortalのKubernetes Securityでは、workflow templateやserving templateで適切なKubernetes security featuresを有効にすることが推奨されている。代表的な制約として、non-root実行、privilege escalation禁止、capabilities drop、特定のuser/group設定などが挙げられている。

Basisが直接YAMLを書くとは限らないが、レビュー観点は持てる。

  • root userで動く前提のimageをAI Coreへ持ち込んでいないか
  • allowPrivilegeEscalation や追加capabilityを要求するimageになっていないか
  • secretを環境変数やログへ出していないか
  • workload templateの修正履歴と承認者を残せているか
  • 本番resource groupと検証resource groupを同じobject store資格情報で共有していないか

3. Service keyは「接続情報」ではなく「特権資格情報」として扱う

SAP AI Coreの初期設定では、BTP cockpitからservice instanceを作成し、service keyを発行する。service keyにはSAP AI CoreへアクセスするためのURLとcredentialが含まれる。公式資料では、access credentialやcertificateのローテーションは利用者側の責任として明記されている。

運用チェックリストとしては、以下を月次または変更時に確認する。

  • service keyの保管先が個人端末や共有メモに散らばっていないか
  • x.509 certificateを使える場面ではclient secretより短い有効期限で運用できるか
  • key発行者、用途、対象resource group、最終利用日を台帳化しているか
  • 不要なservice keyを削除できているか
  • admin scopeが必要な自動化と、read/runだけでよい自動化を分けているか

SAP Communityの認証エラー解説でも、resource group作成時のRBAC access deniedはtoken期限切れではなく、service keyに管理scopeが足りないケースとして説明されている。これは障害対応時の一次切り分けにも使える。

4. AI Launchpad側のrole collectionを監査対象にする

SAP AI LaunchpadのSecurity資料には、AI Core Administration appのrole collectionとscopeが整理されている。repositories、applications、docker registry secrets、object store secrets、generic secrets、resource groupsなど、それぞれviewer/editor系の権限が分かれる。

Basis向けには「広いadminを少人数に集める」だけでは不十分で、以下の職務分離が必要になる。

  • repositoryやapplicationを変更できる人
  • docker registry secretやobject store secretを閲覧・更新できる人
  • resource groupを作成・削除できる人
  • deploymentやexecutionを起動・停止できる人
  • audit logを読む人

特にsecret系のviewer/editor権限は、単なる閲覧権限ではなくcredential露出リスクとして扱う。

5. Security Patch DayはABAPだけでなくAI/BTPの棚卸し日にする

SAP Security Notes & Newsでは、SAP Security Patch Dayが毎月第2火曜日に設定されている。2026年の日付にも6月9日が掲載されている。AI Core運用では、この日にSAP Noteだけを見るのではなく、以下もまとめて確認すると実務に落ちる。

  • SAP AI Core / AI Launchpad / Generative AI Hub関連のSecurity Noteや重要告知
  • SAP Cloud SDK for AI、AI SDK、npm/Python packageのバージョンと脆弱性情報
  • Docker base image、private registry、CI/CD runnerの更新状況
  • BTP subaccountのrole collection差分
  • service key、generic secret、object store secretの作成・削除ログ
  • 本番resource groupのdeployment一覧と最終実行日

個人向けの読みどころ

これはSAP Basisコンテンツ化しやすい。タイトルは「SAP AI Core時代のBasis運用チェックリスト」くらいにすると、JouleやBusiness AIの華やかな話から一段下げて、実際に誰が何を見続けるのかという運用論にできる。

特に強い切り口は「AI CoreはKubernetesを知らなくてよいサービスではなく、Kubernetes的な失敗をBTP運用に翻訳して見る対象」という点。Basis担当者向けには、以下の5枚構成でYouTube/記事化できる。

  1. AI CoreでBasisが見る場所
  2. service keyとresource groupの危険な使い方
  3. Kubernetes securityで弾かれるtemplateの典型
  4. role collectionとsecret権限の棚卸し
  5. Security Patch Dayに追加する月次チェック

注意点

このメモは公開資料からの運用観点整理であり、SAP契約、RISE運用範囲、個別BTP環境の責任分界を断定するものではない。実環境へ適用する場合は、利用中のSAP契約、BTP subaccount設計、社内セキュリティ基準、SAP公式サポートの最新情報を確認する必要がある。

また、SAP Help PortalのPDFやオンライン文書は更新される。特にAI Core、Generative AI Hub、AI SDK、role collectionの名称やscopeは変更される可能性があるため、チェックリスト化する場合は「確認日」と「参照URL」を残す。
