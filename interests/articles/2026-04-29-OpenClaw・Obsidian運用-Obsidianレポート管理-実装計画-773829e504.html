Obsidianレポート管理 実装計画

目的

Mandayが生成するMarkdownレポートを、Mac mini上のObsidianで検索・閲覧・蓄積・再利用できるようにする。

前提

  • 現在のレポート保存先: [内部パス]
  • 既存レポートはこのフォルダへ移動済み。
  • obsidian-cli は /opt/homebrew/bin/obsidian-cli に存在。
  • Obsidian本体とVault設定は未検出。
  • 短期方針: [内部パス] をそのままVault化。
  • 中長期方針: [内部パス] など専用Vaultへ移行。

実装方針

Phase 0: 事前決定

個人さんに確認する意思決定:

  1. 短期運用として [内部パス] をObsidian Vaultにしてよいか。
  2. 中長期で専用Vaultへ移行するタイミングをいつにするか。
  3. バックアップ方式をどれにするか。
  • Time Machine
  • Git
  • Obsidian Local Backup plugin
  • 上記の併用

推奨: まず[内部パス]

Phase 1: Obsidian本体インストールとVault作成

作業:

  1. Obsidian本体をMac miniへインストール。
  2. Obsidianで [内部パス] をVaultとして開く。
  3. .obsidian/ が作成されることを確認。
  4. Obsidian上で既存レポートが表示・検索できることを確認。

完了条件:

  • /Applications/Obsidian.app が存在する、またはObsidian本体のインストール先が確認できる。
  • ~/Library/Application Support/obsidian/obsidian.json にVault情報が登録されている。
  • [内部パス] がVaultとして認識される。

Phase 2: Vault初期整備

[内部パス] Vault内に以下を作る。

``text [内部パス] ├── Indexes/ │ └── Reports Index.md ├── Topics/ │ ├── Obsidian運用.md │ ├── レポート管理.md │ └── 不動産投資.md ├── Templates/ │ └── Report Template.md └── Attachments/ ``

初期索引に既存レポートをリンクする。

完了条件:

  • Indexes/Reports Index.md から既存レポートへ辿れる。
  • Topics/ に主要テーマノートがある。
  • 新規レポートのRelatedリンク先が存在する。

Phase 3: Mandayレポートテンプレート標準化

task-queue/PROCESSING.md とキュー処理スキルのテンプレートを拡張する。

標準frontmatter:

```yaml --- title: レポートタイトル created: YYYY-MM-DD updated: YYYY-MM-DD type: report status: done source_task: TASK_ID category: general area: asset_type: tags:

  • research
  • report

related:

  • "[[レポート管理]]"

--- ```

標準本文構成:

```markdown

タイトル

Summary

結論

調査条件

Findings

Sources

不確実性・注意点

次アクション候補

メモリ保存候補

Related

```

完了条件:

  • 新規レポートがObsidian Propertiesとして読みやすい。
  • source_task でキューIDと紐づく。
  • Related が必ずある。

Phase 4: report系スキルの整備

対象:

  • skills/report-list/
  • skills/report-show/
  • skills/report-send-file/
  • 必要なら新規 report-index-update skill

作業:

  1. すべてのスクリプトが [内部パス] を参照しているか確認。
  2. Indexes/Reports Index.md を更新する補助スクリプトを作る。
  3. レポート完了後に索引更新できる導線を追加。

完了条件:

  • 「レポート一覧」「001を送って」「キーワードで見せて」が[内部パス]
  • 新規レポートが索引に追加される。

Phase 5: obsidian-cli設定

作業:

  1. Obsidian本体インストール後にVault登録状況を確認。
  2. obsidian-cli set-default "report" またはVault名に応じた設定を実行。
  3. obsidian-cli print-default --path-only で確認。
  4. obsidian-cli search-content "不動産投資" が動くか確認。

完了条件:

  • CLIからデフォルトVaultを参照できる。
  • CLI検索が使える。
  • 将来の移動・リネーム時に obsidian-cli move を使える。

Phase 6: バックアップ

短期推奨:

  • Time MachineでMac mini全体をバックアップ。

中期推奨:

  • VaultをGit管理する。
  • .gitignore に以下を入れる。

``gitignore .obsidian/workspace.json .obsidian/workspaces.json .DS_Store ``

完了条件:

  • 少なくとも1つの復旧手段がある。
  • Syncだけに依存していない。

Phase 7: 専用Vault移行判断

[内部パス]

移行先案:

``text [内部パス] ├── Reports/ ├── Topics/ ├── Indexes/ ├── Templates/ └── Attachments/ ``

移行作業:

  1. MandayVault を作成。
  2. 既存レポートを Reports/ へ移動。
  3. queue_task.py の REPORTS_DIR を更新。
  4. report系スキルの参照先を更新。
  5. Obsidian default vaultを更新。
  6. リンク・索引を再生成。

移行判断基準:

  • レポート以外のノートが増える。
  • 添付ファイルやテンプレートが増える。
  • 分野別フォルダ管理が必要になる。
  • Git/バックアップをVault単位で管理したくなる。

推奨実行順

  1. 個人さん確認: [内部パス]
  2. Obsidian本体インストール。
  3. [内部パス]
  4. Indexes/Topics/Templates/Attachmentsを作成。
  5. Reports Index.md を作成。
  6. Mandayレポートテンプレートを標準化。
  7. report系スキルを再検証。
  8. obsidian-cli default vaultを設定。
  9. バックアップ方式を決めて設定。
  10. しばらく運用してから専用Vault移行を判断。

リスクと対策

  • [内部パス]
  • 対策: Indexes/, Topics/, Templates/, Attachments/ を作り、レポート本体は当面直下に置く。
  • Obsidian本体が未インストール
  • 対策: Phase 1で先に解消。
  • Syncをバックアップと誤認する
  • 対策: Time Machine/Git/Local Backupのいずれかを別途設定。
  • タグが乱立する
  • 対策: 共通タグ・領域タグ・補助タグに制限する。
  • スクリプトの参照先が旧パスに残る
  • 対策: grep -R "task-queue/reports\|[内部パス]" で実装後に確認。

Manday側で次に実装できること

個人さんの許可があれば、次の順番で実装可能。

  1. [内部パス], Topics, Templates, Attachments を作成。
  2. Reports Index.md を既存レポートから生成。
  3. task-queue/PROCESSING.md のテンプレートを拡張。
  4. report系スキルのスクリプト参照先を点検・修正。
  5. Obsidian本体インストール後にCLI default vaultを設定。

保留事項

  • Obsidian本体インストールは外部アプリ導入なので、個人さんの明示許可後に実行する。
  • 専用Vaultへの移行は、現在のFinderアクセスしやすさとのトレードオフがあるため、即時実施せず運用後に判断する。
