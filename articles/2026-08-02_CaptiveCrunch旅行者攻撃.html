2026-08-02 Security importance: high
Summary

Midnight Blizzard系Storm-2945がホテル等のcaptive portal経由でDNS/HTTPを操作し、AiTMフィッシングやマルウェア配布を行う攻撃。

CaptiveCrunch旅行者攻撃

要約

Microsoft Threat Intelligenceは、Midnight Blizzardのサブクラスターと評価するStorm-2945が、ホテル、会議施設、空港などのcaptive portalを持つネットワークを悪用し、旅行者の通信を攻撃者管理インフラへ誘導するキャンペーンを報告した。Microsoftはこの活動をCaptiveCrunchと呼んでいる。

攻撃は、単なる偽Wi-Fiやフィッシングページではない。侵害された、または管理系が悪用された可能性のあるcaptive portal環境でDNS/HTTPトラフィックを操作し、Microsoft 365を模したAiTMフィッシング、Entra IDのdevice code phishing、偽ブラウザ/OS更新を装ったマルウェア配布へつなげる。Windows向けRATや情報窃取、Android APK誘導の兆候も報告されている。

出張者やイベント参加者は「ホテルWi-Fiに出る認証画面だから安全」と見なしやすい。そこにMicrosoftログイン、接続確認、更新案内、ClickFix風の手順が混ざることで、通常の社外アクセス対策では見落としやすい初期侵害経路になる。

背景

Captive portalは、公共・宿泊・会議施設Wi-Fiで最初に表示される認証、同意、部屋番号入力などの画面を指す。利用者はOSやブラウザの接続確認によって自動的にこの画面へ誘導されるため、通信経路やDNS応答が通常よりも柔らかい状態になる。

Microsoftの報告では、Storm-2945は2026年5月初旬以降、複数国のホスピタリティ関連ネットワークやcaptive portal機器に関係するネットワークで、DNS/HTTPを操作してユーザーを攻撃者管理基盤へ転送していた。Microsoftは初期侵害ベクトルの調査中としつつ、複数の被害ネットワークで使われる機器や管理システムに共通点があるため、個別施設の単発侵害に限られない可能性を示している。

Storm-2945は、2026年2月以降にAI支援を含むdevice code/OAuth code phishingを行い、Entra device registrationやMicrosoft 365データ収集につなげていたとされる。今回の特徴は、その手口を旅行者が使うゲストネットワークの文脈へ接続した点にある。

何が重要か

観点内容見るべきポイント
初期接点ホテル、会議施設、空港などのcaptive portal付きネットワーク出張者・イベント参加者の社外アクセス経路
認証攻撃Microsoft 365を模したAiTM、Entra ID device code phishingdevice code flowの許可範囲、条件付きアクセス、異常OAuth検知
端末侵害偽ブラウザ/OS更新、ClickFix風手順、Windows RAT、Android APK誘導「接続確認」「更新」「証明書」「修復ツール」のWeb誘導を禁止する
情報窃取ブラウザCookie、認証情報、Microsoft 365/Azure ADトークン、キー入力、ファイル端末EDRとIDログを同じ事件として相関する
攻撃者像Midnight Blizzard系Storm-2945政府、外交、NGO、ITサービス、企業出張者を高リスクとして扱う

一番の論点は、信頼境界が「社内ネットワークかどうか」だけでは決まらないこと。管理された端末とMFAがあっても、利用者が正規のMicrosoft device code入力ページで攻撃者のコードを承認すれば、攻撃者セッションにトークンを渡してしまう。

また、攻撃者はcaptive portalの自然なユーザー体験を利用する。Wi-Fi接続直後にブラウザが自動で開き、何かを入力したり、更新や接続修復を促されたりする流れは、多くの人にとって違和感が小さい。そこにClickFix的な「このコマンドを実行してください」「このAPKを入れてください」が混ざると、技術者でも疲れている移動中には判断を誤りやすい。

自分向けメモ

  • 出張中の機密作業は、ホテルWi-Fiよりモバイル回線、eSIM、企業管理ホットスポット、信頼済みVPN経路を優先する。
  • captive portalから提示される更新、証明書、ブラウザ修復、セキュリティツール、APKはインストールしない。OS標準の更新経路だけを使う。
  • Entra IDのdevice code flowは、必要な業務がなければブロックを検討する。必要な場合も条件付きアクセスで場所、端末準拠、リスク、アプリを絞る。
  • 出張者向けの教育は「怪しいWi-Fiに入るな」だけでは弱い。「正規Microsoftページに見えるdevice code入力でも、誰がコードを発行したか分からなければ拒否する」と具体化する。
  • EDRではWi-Fi接続直後のNCSI/captive portal確認後にファイル作成やPowerShell実行が起きていないかを見る。ID側では異常なOAuth device code authentication activityを確認する。
  • 企業イベントや会議で会場Wi-Fiを使わせる場合、SSID、captive portal、参加者属性情報の入力項目、代替回線を事前に確認する。
