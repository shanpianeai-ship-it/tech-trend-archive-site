GLM-5.2 ローカルLLM性能・必要マシン調査レポート

作成日: 2026-07-06 注記: 依頼文の「GTM5.2」は、公開情報上は該当するローカルLLMが確認できなかったため、Z.ai の GLM-5.2 と仮定して調査した。

結論

GLM-5.2 は、ローカルで動かせるオープンウェイト系としては極めて大きいフロンティア級 MoE モデルである。性能面では、Z.ai の公表値で SWE-bench Pro 62.1、Terminal-Bench 2.1 81.0、GPQA-Diamond 91.2、AIME 2026 99.2 とされ、特に長文脈コーディング/エージェント用途を強く意識したモデルである。

一方、家庭用PCで「GPUのVRAMだけに全載せ」するモデルではない。Unsloth GGUF を使えば 1-bit/2-bit 量子化でローカル実行は現実的になるが、目安は 256GB級のRAMまたはユニファイドメモリ + 24GB級GPU である。快適性を求めるなら、Mac Studio 256GB以上、または RTX 4090/3090 24GB + 256GB RAM 以上が実用下限になる。

サーバー用途でフル性能/長コンテキストを狙う場合は、8xH200、8xB200、8xH100級のマルチGPUノードが対象になる。特に 1M context を安定して扱うには、vLLM では 8xB200、SGLang の W4AFP8 量子化では 8xH200 が目安として示されている。

モデル概要

  • 開発元: Z.ai
  • ライセンス: MIT
  • アーキテクチャ: MoE
  • 総パラメータ: 約 743B-753B
  • アクティブパラメータ: 約 39B-40B/token
  • コンテキスト長: 1,048,576 tokens
  • 最大出力: 128K tokens
  • 主用途: 長文脈コーディング、エージェント、推論、ツール利用
  • 対応実行系: SGLang、vLLM、Transformers、KTransformers、Unsloth/llama.cpp GGUF

評価上の特徴は、単発QAよりも「長い文脈を保持したまま、複数ステップの開発・修正・検証を進める」用途に寄っている点である。Z.ai docs も、プロジェクト単位のコードベース理解、長時間リファクタリング、モバイル実機デバッグ、Mini Program/ゲーム開発、研究再現などを代表ユースケースとして挙げている。

ローカル実行に必要なメモリ

Unsloth の GLM-5.2 GGUF ガイドでは、必要量を「VRAM + RAM、またはMacのユニファイドメモリの合計」として示している。

量子化必要メモリ目安コメント
1-bit223GB最小構成寄り。品質低下はあるが動作範囲に入る
2-bit245GB現実的なローカル実行の中心。UD-IQ2_M は約239GB
3-bit290-360GB品質と必要メモリの中間
4-bit372-475GB品質重視。家庭用単体マシンでは重い
5-bit570GBワークステーション/サーバー級
8-bit810GBほぼサーバー級

重要なのは、これは「GPU VRAMだけ」の要求ではない点である。GGUF + llama.cpp/Unsloth Studio では、GPUに一部を載せ、残りをRAMにオフロードして動かす構成が前提になる。

マシン構成別の実用判断

構成実行可否所感
16-64GB RAMの一般PC不可モデル本体が載らない
128GB RAM + 12/16GB VRAM厳しい1-bitでも不足しやすい
256GB RAM + RTX 3090/4090 24GB可2-bit GGUFの実用下限。速度は期待しすぎない
256GB unified memory Mac Studio可2-bit GGUFに向く。VRAM/RAM分断がない利点あり
512GB RAM + 24-48GB VRAM良好3-4bitも検討範囲
4x RTX 3090/4090 + 256GB RAM良好GPUオフロード量を増やせる。電源/発熱/PCIe帯域に注意
8xH100サーバー用途W4AFP8では約400K context目安。FP8は厳しいとの報告あり
8xH200サーバー用途で有力W4AFP8なら1M context、SGLangで実測値あり
8xB200フル1M context向けvLLM recipe が 1M context の目安として提示

家庭用で買うなら、最初の現実ラインは 256GBメモリ + 24GB GPU。VRAMだけで考えるなら、24GB GPU 1枚では足りず、RAMオフロード前提になる。完全GPU常駐や高スループット運用を狙うなら、H200/B200級のサーバー領域になる。

推論速度の目安

公開情報で具体的な速度が確認できたのは、PhalaCloud の GLM-5.2-W4AFP8 で、8xH200 + SGLang 構成の値。

条件速度
Single-stream decode、投機デコードなし75 tok/s
Single-stream decode、EAGLE/MTPあり118 tok/s
8K入力/1K出力、16並列、投機デコードなし658 tok/s
8K入力/1K出力、16並列、EAGLE/MTPあり733 tok/s

この値はH200サーバーの話であり、256GB RAM + 24GB GPU のGGUFローカル実行では大きく下がると見るべきである。家庭用構成では「動く」「長い文脈で試せる」が主目的で、商用APIのような応答速度は期待しない方がよい。

推奨構成

個人検証・趣味用途

  • Mac Studio 256GB unified memory
  • または Windows/Linux PC: 256GB RAM + RTX 4090/3090 24GB
  • 実行方式: Unsloth Studio または llama.cpp GGUF
  • 量子化: UD-IQ2_M から開始。動作優先なら 1-bit、品質重視なら 3-bit以上

ローカルで多少本格的に使う

  • 512GB RAM
  • 24GB-48GB VRAM GPUを1-2枚以上
  • 量子化: 2-bit/3-bit/4-bitを用途で使い分け
  • 注意: CPU/RAMオフロード比率、ストレージ速度、冷却、電源が効く

チーム内API・高スループット

  • 8xH200 または 8xB200 ノード
  • vLLM または SGLang
  • FP8 KV cache、MTP/speculative decoding を活用
  • フル1M contextを重視するなら、8xB200またはW4AFP8 on 8xH200を検討

導入上の注意点

  • モデルサイズが非常に大きいため、ダウンロードだけで数百GB単位の空き容量が必要。
  • 2-bitでもモデルファイルが約239GBあるため、SSDは最低でも1TB級、余裕を見るなら2TB以上が望ましい。
  • 長コンテキストを使うほどKV cacheが増え、同時実行数を上げるほどメモリを消費する。
  • 量子化モデルでは品質が落ちる可能性がある。UnslothはDynamic 2-bitで「約82% top-1 accuracy」と説明しているが、これは一般的な正答率そのものではなく、BF16/Q8とのlogit分布差に近い指標である。
  • ツール利用・コーディング用途では、モデル単体だけでなく実行ハーネス、ファイル操作、安全制約、テスト実行環境が成果を左右する。

候補1: Mac Studio M3 Ultra 256GB unified memory

最も分かりやすい候補。MacのユニファイドメモリはCPU/GPUで共有されるため、Windows自作機のように「VRAM 24GB + RAM 256GB」の間を明示的に分けて考える必要が薄い。GLM-5.2の2-bit GGUFのように、モデルファイルだけで約239GB級になるものを試す場合、256GB unified memoryはぎりぎり実用圏に入る。

購入先候補:

  • Apple Store Mac Studio
  • Apple Store Mac Studio M3 Ultra 256GB構成
  • JRE MALL Apple Rewards Store Mac Studio 256GB/4TB
  • ANA Mall Apple Rewards Store Mac Studio 256GB/16TB

価格メモ:

  • Apple Rewards系モールでは、M3 Ultra 32コアCPU/80コアGPU/256GB/16TB構成が税込1,883,800円として検索結果に表示された。
  • 4TB構成はApple公式/各モールで要確認。SSD容量を落とせば総額は下がるが、GLM-5.2用途ではモデル置き場だけで数百GB必要なので、最低2TB、できれば4TB以上が扱いやすい。

向く人:

  • CUDAよりも「とにかく大容量メモリでローカルLLMを触る」ことを優先する人。
  • 電源、騒音、発熱、組立、相性問題を避けたい人。

注意点:

  • NVIDIA CUDA前提のAIツールや最適化は使いにくい。
  • 256GBは2-bit GGUFのぎりぎりラインなので、他アプリを大量に開いた状態では余裕が少ない。

候補2: RTX 5090 32GB + 256GB RAM のWindows/Linux自作機

2026年時点で新規購入するなら、RTX 4090よりRTX 5090を検討する価値が高い。RTX 5090は32GB VRAMで、GLM-5.2全体を載せるには足りないが、GGUF/llama.cpp/UnslothのGPUオフロード量を増やしやすい。

構成例:

  • CPU: Ryzen 9 9950X / 9950X3D、またはCore Ultra 9級
  • RAM: DDR5 256GB。64GB x4、または対応マザーで128GB x2/4
  • GPU: RTX 5090 32GB
  • SSD: NVMe 4TB以上推奨
  • 電源: 1200W以上、ATX 3.1/12V-2x6対応を推奨
  • OS: LinuxまたはWindows + WSL2

購入先候補:

  • Amazon.co.jp RTX 5090検索
  • 価格.com MSI GeForce RTX 5090 32G VENTUS 3X OC
  • TSUKUMO RTX 5090商品例
  • GIGABYTE RTX 5090 32G仕様

価格メモ:

  • 価格.comでMSI RTX 5090 32GBの最安が709,800円、在庫ありとして確認できた。
  • RTX 5090単体で70万円前後、256GB RAM/CPU/マザー/電源/SSD/ケース込みで、全体は120万-170万円級を見ておくのが現実的。

向く人:

  • CUDA対応、画像生成、動画生成、ローカルLLMを同じマシンで試したい人。
  • Windows/LinuxのAI環境構築に慣れている人。

注意点:

  • 256GB DDR5を一般向けマザーで安定動作させるには、マザーボードのQVL確認が必要。
  • RTX 5090は消費電力が大きい。電源、ケーブル、冷却、ケース寸法を軽視しない。

  • 価格.com RTX 4090 24GB検索
  • TSUKUMO RTX 4090搭載BTO例

価格・購入先の見方

  • Amazonは在庫と価格の変動が大きく、並行輸入・マーケットプレイス出品も混ざる。高額GPUは販売元、保証、返品条件を必ず確認する。
  • 価格.comは相場把握に便利だが、最終的な在庫・送料・保証はショップ側で確認する。
  • BTOは標準構成が32GB/64GB RAMのことが多い。GLM-5.2用途では、注文前に256GB RAMへ増設できるかを確認する。
  • 自作なら、マザーボードのメモリQVL、4 DIMM時の安定性、電源容量、GPU寸法、12V-2x6/12VHPWRケーブルの取り回しを確認する。

現時点のおすすめ

最も無難なのは Mac Studio M3 Ultra 256GB unified memory。GLM-5.2の2-bit GGUFを「とにかくローカルで動かす」目的には一番失敗しにくい。

CUDAや画像/動画生成も含めて遊ぶなら RTX 5090 32GB + 256GB RAM のWindows/Linux機 が有力。RTX 4090 24GBは下限として成立するが、新品価格が高いならRTX 5090を優先して比較した方がよい。

安定運用や長時間ジョブを重視するなら ThinkStation P8 / Dell Precision 7875 / HP Z8 Fury G5 のようなワークステーション。ただし家庭用としては予算がかなり重い。
