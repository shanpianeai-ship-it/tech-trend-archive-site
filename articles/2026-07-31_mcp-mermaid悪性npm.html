2026-07-31 Security importance: high
Summary

npmのmcp-mermaidに悪性preinstallが混入したGitHub Advisory。MCPツールを便利さだけで導入せず、依存・CI・秘密情報を同時に守る必要が分かる。

mcp-mermaid悪性npm

要約

GitHub Advisory Databaseは、npmパッケージ mcp-mermaid の 0.5.1 と 0.6.1 に悪性コードが含まれていたと報告している。内容は、Mini Shai-Hulud系のサプライチェーン攻撃キャンペーンの一部で、preinstall hookから難読化されたBunスクリプトを実行し、クラウド鍵、GitHub PAT、npm token、Kubernetes service account token、SSH鍵、Docker認証情報などを盗むものとされる。

この件が重要なのは、MCP関連ツールが「LLMエージェントに便利な小物」ではなく、開発端末、CI/CD、クラウド認証情報に触れる通常のnpm依存として攻撃対象になっている点。MCPサーバーや周辺パッケージを試す速度が上がるほど、パッケージ導入時の権限、実行hook、秘密情報の露出範囲を見直す必要がある。

背景

mcp-mermaid はMermaid図を扱うMCP関連パッケージとして見えるが、GitHub Advisoryではこのパッケージが大規模なnpm侵害キャンペーンの一部として改ざんされたと説明されている。

Advisoryによると、攻撃者はnpmアカウントを侵害し、短時間に多数のパッケージへ悪性バージョンを公開した。悪性版はインストール時に実行される preinstall hookを使い、GitHub APIを秘密情報の流出経路として利用したとされる。さらにGitHub Actions workflowの注入、AI agent session hooks、システムdaemonによる永続化にも触れられている。

npmレジストリ上では、0.5.1 と 0.6.1 はversions一覧から外れており、latest は 0.4.1 に戻っている。ただしGitHub Advisory上のpatched versionsはNoneで、悪性コード扱いのため単純な「修正版へ上げれば完了」とは読まない方がよい。

何が重要か

観点今回の事実実務上の意味
侵入点npmの preinstall hooknpm install だけで端末やCI上の秘密情報に触れ得る
対象領域MCP関連パッケージAIエージェント周辺の実験用ツールもサプライチェーン管理対象
影響情報クラウド鍵、PAT、npm token、Kubernetes tokenなど開発者端末とCIの権限分離がないと被害範囲が広がる
継続性workflow注入、agent hooks、daemonへの言及一度消すだけでなく永続化痕跡の確認が必要
対応patched versionsなし影響版を避け、導入履歴と秘密情報ローテーションを確認する

MCPは「外部ツールをLLMに渡すための接続面」なので、ユーザー視点ではプロンプトやツール権限に目が行きやすい。しかし実装上はnpm、Python、Docker、CI、クラウド認証の普通のサプライチェーン問題でもある。

特に個人や小規模チームでは、MCPサーバーをローカルで試す時にGitHub token、クラウドCLI認証、Obsidianやローカルファイルへのアクセス権限が同じ環境に置かれやすい。ここにインストール時実行の悪性コードが入ると、LLMが悪用される前に通常の開発環境として突破される。

自分向けメモ

  • MCPサーバーは「エージェント用プラグイン」ではなく「実行権限を持つ依存」として扱う。
  • 試用するMCP関連npmは、package.json の scripts、公開履歴、maintainer、急なバージョン増減を確認する。
  • AI実験用のNode環境は、普段のGitHub PATやクラウド管理者権限を持つ端末環境から分ける。
  • CIでMCPツールやAI補助ツールを入れる場合、install scriptの実行可否、secretのスコープ、pull requestからの実行条件を確認する。
  • 影響版を入れた可能性がある場合は、単なるアンインストールではなく、npm/GitHub/クラウド/Kubernetes/SSH/Docker/Slackなどの秘密情報ローテーションを検討する。
  • npm install --ignore-scripts は万能ではないが、未知のCLI/MCPツールを調査する初回観察では選択肢になる。
