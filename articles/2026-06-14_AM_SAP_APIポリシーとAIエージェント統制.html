SAP APIポリシーとAIエージェント統制

要約

SAPのAPI Policy更新は、単なるAPI利用制限ではなく、agentic AI時代のERPアクセス制御を整える動きとして見るべき内容。DiginomicaのSAP CTO Philipp Herzig氏への取材と、SAP公式FAQを合わせると、狙いは「外部AIを締め出すこと」よりも、公開済みAPI、監査可能なID、レート制御、SAP Integration Suite / MCP Gateway / A2A などの統制経路へ誘導することにある。

今回のDiscordポールでは候補6「SAP API Policyと組織記憶」に1票が入り、他候補は0票だったため、このテーマを採用した。

背景

SAPは2026年春にAPI Policy FAQを更新し、API利用の目的、レート制御、非公開API、AIエージェント経由のアクセス、大規模データ抽出の扱いを整理した。背景には、AIエージェントや自動化ツールが人間の操作よりも大量かつ予測しにくいAPI呼び出しを発生させる現実がある。

Diginomicaの記事では、Herzig氏が「良いエージェント」だけでなく、身元不明の自動化やデータ抽出を行う「悪いエージェント」も存在すると説明している。SAP側から見ると、API GatewayやCDN、監査ログ、デジタルIDを使って、誰が何をしているかを識別できる経路に寄せる必要がある。

特に論点になるのは、オンプレミス / Private Cloud で見えていたSAP内部インターフェースを、外部連携やAIエージェントが事実上の公開APIとして使ってよいのかという点。SAPは、公開済みAPIや公式ドキュメントで許可された使い方と、SAP内部・非公開・用途外のインターフェース利用を分けようとしている。

何が重要か

第一に、AIエージェント接続では「APIを呼べるか」ではなく「どの統制面を通るか」が重要になる。SAP公式FAQは、AI駆動・agentic・自動化アクセスについて、SAPが endorsed architecture と呼ぶ経路に合わせることを求めている。MCP Gateway on SAP Integration Suite、A2A、Joule / Agent Gateway、SAP Business Data Cloud などが、この文脈での入口になる。

第二に、従来の連携基盤とAIエージェントは負荷特性が違う。決め打ちのIF連携やRPAは、比較的予測しやすい呼び出し列を持つ。一方でLLMオーケストレータは、1つの依頼から探索的に数百から数千のAPI呼び出しを生む可能性がある。ERPのトランザクションAPIをそのまま探索対象にすると、性能、監査、認可、データ整合性のリスクが一気に上がる。

第三に、組織記憶の論点がAPI統制とつながる。Herzig氏は、AIエージェントがより高い自律性を持つには、構造化データだけでなく、判断履歴、業務上の暗黙知、意思決定の痕跡が必要だと説明している。ただし、それをERP周辺で使うなら、出所、検証、更新、権限境界を持ったコンテキストレイヤーが必要になる。

論点従来連携AIエージェント時代
呼び出し量設計時に見積もりやすいプロンプト次第で急増し得る
認可システムIDやユーザーID中心エージェントID、委任、利用者権限の分離が必要
監査IF単位のログで追いやすい推論、ツール選択、API呼び出しの対応付けが必要
データ取得バッチ、ODP、CDS、APIなど用途別探索的な横断取得をどう制限するかが焦点
統制経路iPaaS、RFC、OData、API管理MCP Gateway、A2A、Agent Gateway、BDCが加わる

自分向けメモ

  • SAP Basis / ERP運用目線では、これは「SAPがAPIを有料化するか」だけでなく、AIエージェントが本番ERPへ触るときの境界設計問題として読むべき。
  • MCPサーバーを自前で立ててSAP RFCやODataへ直結する設計は、検証環境では速いが、本番では監査・ID・レート制御・権限委任の説明責任が重い。
  • SAP Integration Suiteを必ず使うべき、という単純な話ではない。FAQ上はサードパーティiPaaSや独自連携も否定されていない。ただし、公開済みAPI、文書化された用途、API Control内の使い方であることが前提になる。
  • RISE移行やPrivate Cloud化のタイミングでは、既存連携がSAP内部・非公開・用途外のインターフェースに依存していないかを棚卸しする価値が高い。
  • 将来のJoule / Agent Gateway / MCP Gateway構成を考えるなら、まず「誰の権限で」「どの業務文脈で」「どのAPIを」「どの回数まで」「どのログで追えるか」を設計メモにする。
