Claude FableとMythosの運用設計

要約

Anthropic は 2026年6月9日、Claude Fable 5 と Claude Mythos 5 を発表した。Fable 5 は一般提供される Mythos-class モデルで、Mythos 5 は同じ基盤モデルから一部セーフガードを外した限定提供版という位置づけ。

単なるベンチマーク更新ではなく、「長時間エージェント作業に強い高性能モデルを、どこまで一般提供し、どこから信頼済みアクセスに分けるか」という運用設計の発表として読むのが重要。

開発・分析・調査では Fable 5 の長時間タスク性能が魅力になる一方、サイバー、バイオ、化学、蒸留関連では安全分類器による拒否やフォールバックを前提に、アプリ側のエラー処理、代替モデル、ログ、データ保持を設計する必要がある。

背景

Anthropic は 4月に Mythos Preview を Project Glasswing 経由で限定提供していた。今回の Fable 5 は、その Mythos-class 能力を一般ユーザーにも広げるための安全強化版に見える。

公式発表では、Fable 5 / Mythos 5 はこれまでの Claude より長時間自律的に動作でき、ソフトウェアエンジニアリング、知識労働、ビジョン、メモリ、生命科学研究で大きな改善があると説明されている。

ただし、能力が高いほど悪用リスクも上がる。Anthropic は、Fable 5 にサイバーセキュリティ、バイオ・化学、モデル蒸留などを検出する分類器を入れ、該当領域では Fable 5 がそのまま答えない設計にしている。

何が重要か

1. モデルの強さより、アクセス制御の分け方が主題

モデル提供範囲主な違い運用上の注意
Claude Fable 5一般提供Mythos-class能力に安全分類器を追加拒否、フォールバック、30日データ保持を前提にする
Claude Mythos 5Project Glasswingなど限定提供Fable 5と同じ基盤で一部制限を解除信頼済み組織向け。一般ユーザーは直接使えない
Claude Opus 4.8既存上位モデルFableの拒否時の代替先にもなる高リスク領域の通常業務では現実的な受け皿

この分け方は、今後のフロンティアAIが「全員に同じモデルを提供する」方向だけでは進まないことを示している。モデル能力、利用者の信頼度、用途の危険度でアクセス層を分ける考え方が強まる。

2. 長時間エージェント運用の現実味が増す

公式発表では、Fable 5 がコードベース規模の移行、複雑な分析、ビジョンのみの長時間タスク、ファイルベースメモリを使う継続作業で強いと説明されている。

自分の用途に引き寄せると、次のような領域で意味がある。

用途期待できること先に設計すべきこと
コード改修大きな変更を計画、実装、検証まで進めるテスト、差分確認、権限、ロールバック
調査ノート作成複数ソースを横断し、長文の構成を保つ出典管理、引用範囲、再調査条件
業務自動化長い手順を途中状態つきで進める監査ログ、人間承認、失敗時停止条件
SAP/ERP運用支援ログ、手順書、変更履歴を横断して仮説を作る本番操作禁止、権限分離、証跡保存

「賢いモデルに任せる」では足りない。長時間動けるほど、作業状態、権限、検証、差し戻しを外側のシステムで持つ必要がある。

3. 拒否とフォールバックを正常系として扱う必要がある

Claude API docs では、Fable 5 が拒否した場合も API 的には HTTP 200 の成功応答になり、stop_reason: "refusal" が返ると説明されている。つまり、アプリ側では通信エラーではなく、モデル判断による分岐として扱う必要がある。

また、サーバー側 fallback、SDK middleware、手動 retry の選択肢が示されている。Fable 5 を組み込むなら、最初から以下を設計しておくべき。

  • refusal を UI とログで明示する
  • Opus 4.8 など代替モデルへ切り替える条件を決める
  • 代替モデルに渡す文脈を最小化する
  • 拒否が多いプロンプトや業務領域をレビューする
  • 危険領域の回避をユーザーに隠さない

これは、モデル選定ではなく運用設計の話。高性能モデルほど「失敗時の見せ方」がプロダクト品質になる。

4. データ保持条件は業務利用の足切りになる

API docs では、Fable 5 / Mythos 5 は 30日データ保持の Covered Models とされ、ゼロデータ保持では使えないと説明されている。

企業利用ではここがかなり大きい。コード、顧客情報、セキュリティ情報、未公開資料を扱うワークフローでは、性能よりもデータ保持ポリシーが先に来る。Microsoft 社内利用制限の報道も、この論点を補強している。

自分向けメモ

  • Fable 5 は「全部これに置き換えるモデル」ではなく、長時間・高難度タスク用の高価な実行レーンとして見る。
  • Cron、Obsidian整理、調査ノート、コード改修のような自分の運用では、Fable級モデルを使うなら作業ログと出典ログを必ず残す。
  • セーフガードで Opus 4.8 へ流れる可能性があるなら、出力品質差や拒否理由を記録できる設計が必要。
  • SAP/ERPやセキュリティ調査では、モデルの能力より「本番系へ触らせない」「証跡を残す」「人間確認を挟む」が重要。
  • 日本語圏では速報記事や概要解説が出始めている。自分用アーカイブでは、ベンチマークの順位より、アクセス制御、データ保持、フォールバック、長時間エージェント運用の設計論として追う。
