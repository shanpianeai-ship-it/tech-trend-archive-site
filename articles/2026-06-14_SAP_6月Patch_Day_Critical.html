2026-06-14 SAP / ERP importance: high
Summary

SAPの2026年6月Security Patch Dayでは、NetWeaver AS ABAP / ABAP Platform、SAP Commerce Cloud、SAP Data Hub、NetWeaver AS Javaなどに関する重要なSecurity Noteが公開された。

SAP 6月Patch Day Critical

要約

SAPの2026年6月Security Patch Dayでは、NetWeaver AS ABAP / ABAP Platform、SAP Commerce Cloud、SAP Data Hub、NetWeaver AS Javaなどに関する重要なSecurity Noteが公開された。特に見るべきは、SAML認証のXML Signature Wrapping、ABAPカーネルのメモリ破壊、Commerce Cloud / Data HubのSpring Security系、NetWeaver AS Java Web Containerのディレクトリトラバーサルである。

今回のポイントは「SAPの月例パッチだから次回定例で見る」では遅い可能性があること。SSO、RFC、Web Container、Commerce Cloudのように、認証境界やリモート到達性に近い箇所が複数含まれるため、Basis運用では対象コンポーネントの有無、外部公開、SAML利用、RFC到達性を先に切り分ける必要がある。

背景

SAP Security Patch Dayは毎月第2火曜日に公開される。SAP公式のSecurity Notes & Newsでは、SAP Security Noteを優先的に実装すること、NetWeaver系の修正はSupport Packageにも含まれること、2026年6月のPatch Dayが6月9日であることが示されている。

2026年6月分は、SAP公式ページと複数のSAPセキュリティ専門ベンダーが同じ主要論点を挙げている。SAML認証、ABAPカーネル、Commerce Cloud / Data Hub、NetWeaver AS Javaが中心で、単一製品の脆弱性というより、SAPランドスケープ横断の優先順位付けが必要な回である。

SAMLのXML Signature WrappingはSSO境界の問題として扱う

CVE-2026-44748は、SAP公式ではNetWeaver AS ABAP / ABAP PlatformのSAML AuthenticationにおけるXML Signature Wrappingとして扱われている。第三者解説でも、署名済みXMLの検証と実際に参照するID情報のズレが問題になるタイプとして説明されている。

運用目線では、これは単なるABAPアプリの不具合ではなく、SSO境界の信頼モデルに関わる。SAMLを使っている本番系、外部公開ポータル、社内横断IdP連携、複数システムの信頼関係を持つ環境では、影響確認を先に回す。

確認観点見るもの
利用有無対象ABAP系でSAML認証を有効化しているか
到達経路Fiori、ポータル、Web Dispatcher、リバースプロキシ経由の入口
信頼範囲IdP、SP、複数SAPシステム間の信頼関係
暫定策SAML停止が業務上可能か、恒久対応までの入口制限が可能か
監査不自然なログイン、権限昇格、通常と異なるSAML応答の痕跡

「SAMLを止めれば回避」という話が出ても、現実には多くの環境で業務影響が大きい。恒久対応は該当Note適用を前提にしつつ、公開入口の制限、監視強化、対象システムの優先順位付けを同時に行うのが現実的。

ABAPカーネル系はシステム単位ではなくカーネル単位で棚卸しする

CVE-2026-27671は、NetWeaver / ABAP PlatformのApplication Server ABAPで使われるSAP Kernelに関するメモリ破壊として扱われている。候補一覧にもある通り、RFC関連の文脈で優先度が高い。

カーネル系は、個別アプリケーションの利用有無だけで判断しにくい。ECC、S/4HANA、BW、Solution Manager系、周辺ABAPシステムなど、同じカーネル系列を使う環境が広く存在するため、まずランドスケープ全体のカーネル版とパッチレベルを並べる。

優先条件対応メモ
最優先外部または広い社内ネットワークからRFC到達可能到達制限、監視、カーネル更新計画を即時化
高重要業務の中核ABAP、SSOやRFC連携が多い停止時間、HA構成、ロールバック手順を確認
中閉域・限定用途だが対象カーネル定例内でよいかをリスクオーナーと確認
低対象外バージョン、停止済み、隔離済み証跡として対象外理由を残す

Commerce Cloud / Data Hub / AS Javaも後回しにしない

SAP運用ではABAP系に目が行きやすいが、Commerce Cloud、Data Hub、AS Javaも今回のCritical対象に入っている。特にCommerce Cloudは外部顧客接点に近いことが多く、AS Javaは古い連携や管理系用途で残っていることがある。

「使っていないはず」の確認で終わらせず、CMDB、クラウド契約、BTP/Commerce管理画面、監視対象、DNS、リバースプロキシ設定を突き合わせる。存在を見落としたJava系やCommerce系が、実際には外部から到達できる状態になっているのが一番危ない。

自分向けメモ

  • 今回は投票なしのため、運用ルールの選定基準で採用。SAP Basis運用に直結し、日本語で「どれを先に見るか」の整理価値が高い。
  • SAP Patch Dayは「月例」だが、CriticalがSSO/RFC/Web入口に絡む場合は、通常の月次パッチ運用ではなく緊急判定の土俵に載せる。
  • 初動テンプレートは、対象コンポーネント、外部公開、認証方式、RFC到達性、代替制御、停止可否、適用予定、監視強化の8項目でよい。
  • SAML系はIdP/SPの担当境界が分かれやすい。Basis、ID管理、ネットワーク、アプリ運用の誰が何を見るかを切る。
  • ABAPカーネルは「この業務アプリは使っているか」ではなく「このカーネル系列がどこにいるか」で探す。
  • Commerce CloudやAS Javaは台帳から漏れやすい。DNS、WAF、プロキシ、監視対象から逆引きする。
